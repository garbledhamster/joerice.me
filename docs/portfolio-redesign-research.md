# Portfolio redesign research

November 21, 2026 · Source baseline `aec45c0`

- Keep the phone’s swipe native and give every category a keyboard and tap destination. [W3C](https://www.w3.org/TR/WCAG22/#pointer-gestures)
- Use native dialogs and return focus, category and note position after closing. [WHATWG](https://html.spec.whatwg.org/multipage/interactive-elements.html#the-dialog-element)
- Prove rejection and retry in the browser, then verify provider acceptance and inbox delivery. [Formspree](https://help.formspree.io/articles/form-and-project-settings/over-limit-submissions)
- Check public reads and authorized edits with representative Firestore rules and disposable records. [Firebase](https://firebase.google.com/docs/firestore/security/test-rules-emulator)
- Track the lockfile and run read-only checks and real-entry browser journeys in CI. [npm](https://docs.npmjs.com/cli/v11/commands/npm-ci/)

The plan keeps the static GitHub Pages site and its existing Firebase and Formspree boundaries. The main payoffs are a phone layout people can use without a swipe, recoverable contact, accurate visibility after sign-out and a reproducible check on the candidate. Production rules, device behavior and inbox delivery still need their own evidence.

## Phone navigation and access

The phone can keep the folder’s horizontal panels and give visitors a direct way to reach any of the eight categories. Keep the swipe native, use the same category state for the rail and any picker, and give longer content room to scroll vertically inside its panel or sheet. The following checks apply to the redesign once there is a rendered implementation to test.

1. **Reach all eight categories by tap and keyboard.** Use a named navigation landmark with real links when categories are stable destinations. Mark the current in-page link with `aria-current="location"`. The folder tabs can keep their visual shape. Reserve ARIA tabs for a one-panel widget with the tab pattern’s arrow-key behavior and selection state. In the rendered check, reach each category without swiping and verify visible focus, reading order, and the announced current category. Opening a note or following an example should require deliberate activation. Use buttons for opening a note layer and going Back, and links for the example destinations. [WCAG 2.2 Keyboard](https://www.w3.org/TR/WCAG22/#keyboard) · [WCAG 2.2 Pointer Gestures](https://www.w3.org/TR/WCAG22/#pointer-gestures) · [WCAG 2.2 Focus Visible](https://www.w3.org/TR/WCAG22/#focus-visible) · [WAI-ARIA current state](https://www.w3.org/TR/wai-aria-1.2/#aria-current) · [WAI tabs pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)

2. **Snap inside the board and keep each panel readable.** Start with horizontal-only CSS snap and one snap point per panel. Check that a tap can jump directly to the eighth category and a swipe updates the same active state after settling. Keep focus where it is if it remains visible. If the departing panel contains focus, move it to a visible category control before making the panel inactive. Use the visible panel as the source of truth after a swipe. If using `scrollsnapchange`, give browsers that lack it a visibility-based fallback. Offscreen action controls and covered note layers should stay out of the tab order. At 320 CSS pixels wide, including 400% zoom from a 1280 CSS pixel viewport, each panel’s text and controls should fit across the available width without sideways scrolling to read them. Let tall content scroll within the panel. Test the shortest phone layout, zoom, and landscape. Fixed chrome can obscure focus, while mandatory snapping can make content between distant snap points unreachable. Give a constrained layout room to reflow and keep its category controls reachable. [W3C Reflow guidance for carousels](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) · [CSS Scroll Snap §§4.1 and 6.2](https://www.w3.org/TR/css-scroll-snap-1/) · [Chrome scroll-snap state sync](https://developer.chrome.com/docs/modern-web-guidance/guides/ui-behaviors/scroll-snap-state-sync) · [WCAG 2.2 Focus Not Obscured](https://www.w3.org/TR/WCAG22/#focus-not-obscured-minimum)

3. **Open and close sheets with predictable focus.** Use native `<dialog>` with `showModal()` where the quote or detail sheet blocks the board. Give it a visible title and Close button. Focus the heading first when a long sheet would otherwise open partway down. Verify that focus stays within the sheet and browser controls, touch can close it, Escape closes it, and focus returns to the invoking control or a logical choice if that control has disappeared. Check that the board resumes at the same category and note depth. On a phone, open the keyboard and verify that fields, errors and Close remain reachable through the sheet’s own vertical scrolling. [WHATWG dialog element](https://html.spec.whatwg.org/multipage/interactive-elements.html#the-dialog-element) · [WAI native dialog technique](https://www.w3.org/WAI/WCAG22/Techniques/html/H102) · [WAI modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)

4. **Measure the tappable area.** Aim for 44 × 44 CSS pixels for the category choices, note controls, Close and Hire me. The visible ink and paper edge can be smaller. WCAG 2.2 AA sets a 24 × 24 CSS pixel minimum with exceptions including spacing. The 44 × 44 size is the enhanced AAA criterion, with its own exceptions. Verify computed hit regions and actual taps on a short phone, especially where paper edges overlap or rotate. [WCAG 2.2 Target Size (Minimum)](https://www.w3.org/TR/WCAG22/#target-size-minimum) · [WCAG 2.2 Target Size (Enhanced)](https://www.w3.org/TR/WCAG22/#target-size-enhanced)

5. **Keep the same controls when motion is reduced.** With the system’s reduced-motion preference enabled, verify that choosing a category or peeling a note reveals the destination immediately. Drop the toss, travel and authored smooth scrolling in both CSS and JavaScript paths. Confirm that Back, focus changes and note depth work with the same taps and keys in both motion settings. Native finger scrolling can still take visitors between panels. [CSS `prefers-reduced-motion`](https://www.w3.org/TR/mediaqueries-5/#prefers-reduced-motion) · [WAI reduced-motion technique](https://www.w3.org/WAI/WCAG22/Techniques/css/C39)

## Quote, content and delivery

Keep GitHub Pages, the existing Firestore content model, and the Formspree inquiry endpoint. Verify the candidate in the real page with disposable data, verify the Firebase access boundary separately, then check actual quote receipt with one authorized request. This research reviewed the proposed spec and the deployed source at `aec45c08fb1d8bc973096301f6cbb2a204338bb5`. Provider settings and live receipt are open checks. [Deployed source](https://github.com/garbledhamster/joerice.me/tree/aec45c08fb1d8bc973096301f6cbb2a204338bb5)

### Quotes and feedback

- **Keep the current request.** The active app imports `pages/contact.js`. It sends `FormData` to Formspree with `Accept: application/json`. Name, email and message are required. Phone is optional and multiple selected services travel as repeated `services` fields containing their titles. The code asks for a fresh CAPTCHA token at submit when the API is available, then checks `response.ok` before clearing the form or opening confirmation. Test the configured CAPTCHA in a real browser, including script or token failure in the fixture. Google recommends executing reCAPTCHA v3 at the protected action because tokens expire after two minutes. Formspree’s public custom-key guide describes v2, so the effective CAPTCHA setup needs confirmation in the provider account. [Active app entry](https://github.com/garbledhamster/joerice.me/blob/aec45c08fb1d8bc973096301f6cbb2a204338bb5/assets/js/main.js#L8) · [Quote transport](https://github.com/garbledhamster/joerice.me/blob/aec45c08fb1d8bc973096301f6cbb2a204338bb5/assets/js/pages/contact.js#L93) · [Google reCAPTCHA v3](https://developers.google.com/recaptcha/docs/v3#placement_on_your_website) · [Formspree custom reCAPTCHA guide](https://help.formspree.io/articles/form-and-project-settings/adding-a-custom-recaptcha-v2-key/)
- **Make the fixture prove each state.** The current quote double returns immediate HTTP 500 or 200. Its first outcome waits for a request but can skip the assertions if that request never arrives. Make the request count an explicit assertion. Hold a response open to check one in-flight POST across repeat taps or Enter. Assert required-field validation, optional fields, both quote and feedback entry, and the intended payload. Exercise a rejected fetch, a provider rejection and a rate limit, retained values, explicit retry, and a single accepted transition. Display sending and errors where assistive technology can announce them. A network interruption can leave receipt uncertain, so preserve values and avoid automatic repeat POSTs. Use a fallback contact after verifying its destination and publication approval. Fetch requires an explicit status check for HTTP failures, and Formspree documents HTTP 429 for AJAX rate limits. [Current request double](https://github.com/garbledhamster/joerice.me/blob/aec45c08fb1d8bc973096301f6cbb2a204338bb5/tests/single-page-browser-test.html#L177) · [Timeout helper](https://github.com/garbledhamster/joerice.me/blob/aec45c08fb1d8bc973096301f6cbb2a204338bb5/tests/single-page-browser-test.html#L229) · [Current quote assertions](https://github.com/garbledhamster/joerice.me/blob/aec45c08fb1d8bc973096301f6cbb2a204338bb5/tests/single-page-browser-test.html#L311) · [MDN Fetch](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch#checking_response_status) · [Formspree system limits](https://help.formspree.io/articles/form-and-project-settings/system-limits) · [WCAG status messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)
- **Confirm receipt in the browser, Formspree and the recipient’s inbox.** A successful UI response shows provider acceptance. Formspree can save submissions over the monthly limit without sending notifications, and its domain restriction can route submissions to Spam based on the referrer. Confirm the actual account, target recipient, configured protections and authorized browser origin. When authorized, send one marked synthetic request from the approved origin and record the candidate or deployment revision, timestamp, matching Formspree Inbox entry and recipient email. A private preview may use a different referrer, so note the origin whenever recording this check. Use the fixture for repeated checks and keep payloads, CAPTCHA tokens and recipient details out of public evidence. [Formspree over-limit submissions](https://help.formspree.io/articles/form-and-project-settings/over-limit-submissions) · [Formspree domain restriction](https://help.formspree.io/articles/form-and-project-settings/restrict-to-domain) · [Formspree system limits](https://help.formspree.io/articles/form-and-project-settings/system-limits)

### Content and editing

- **Review the deployed Rules before expanding browser editing.** The catalog and public archive query `Posts` with `published == true`. The fixture supplies a fake admin and a local Firestore double. The checkout has no tracked Rules file. Firebase evaluates collection queries against everything they could return and authorizes whole document reads. Keep each publicly readable document fully safe to publish, including fields the UI hides. Review the active rules through authorized access and exercise a representative ruleset with the emulator. Use disposable records to check published list and direct reads, denied draft reads and writes for signed-out and non-admin users, and the intended admin operations. Match the fixture’s public editing and rendering cases to those boundaries. Keep account keys out of static assets. - **Exercise failed reads and old content explicitly.** The catalog starts from defaults and merges published overrides by stable ID. An imported YAML post is saved in a batch with a public marker containing its source path and no post body. The marker suppresses the bundled entry after a successful Firestore read even if the replacement is unpublished or deleted. On a fresh load, the app adds bundled YAML before requesting Firestore, so a failed request can leave suppressed originals in the list. A later failed refresh also leaves the previous arrays intact, and list rendering does not filter by the admin state. Check sign-out during a failed refresh so previously loaded draft titles, filters and open detail clear. Exercise offline or denied reads with overridden originals and unavailable or renamed services. Treat bundled YAML as public, including directly reachable files. Keep any truly private text out of that bundle and use only publication-cleared fallback material. The source has a `package.json` and explicitly ignores `package-lock.json`. Pages built and deployed the same commit. Keep the current branch-based Pages publication and verify its build separately.
